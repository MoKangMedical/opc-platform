# 技能系统：构建你的AI武器库

> **导语**：如果说Hermes Agent是你的"指挥官"，那Skills就是它的"武器装备"。一个没有技能的Agent就像一个只会说话但不会行动的人——能理解你的指令，但什么都做不了。Skills系统是Hermes Agent最核心的扩展机制，也是OPC创业者真正拉开差距的地方。同样的Agent，加载不同的Skills组合，战斗力天差地别。本课程将带你从创建第一个Skill开始，逐步构建属于你自己的AI能力矩阵。

---

## 一、Skills系统架构与设计哲学

### 1.1 什么是Skill？

在Hermes Agent中，**Skill** 是一个自包含的能力模块，定义了Agent"在特定场景下知道什么、能做什么"。技术上，一个Skill包含：

- **知识（Knowledge）**：Markdown格式的指令文档，告诉Agent在这个场景下的操作规范、最佳实践和边界
- **工具权限声明（Optional）**：声明这个Skill需要使用哪些工具
- **触发器（Optional）**：什么情况下自动加载这个Skill

一个Skill可以简单到"告诉Agent如何用特定格式写周报"，也可以复杂到"教会Agent如何部署和维护一个Kubernetes集群"。

### 1.2 设计哲学：可组合的能力单元

Skills系统遵循三个设计原则：

**原则一：单一职责**
每个Skill只做一件事，而且把它做到极致。`github-issue-creator` 只负责创建Issue，不涉略PR管理。这让你可以像搭乐高一样自由组合。

**原则二：声明式知识**
Skill不是代码，是知识文档。它用自然语言告诉Agent"怎么想、怎么做"，而非硬编码逻辑。这让非程序员也能创建和修改Skill。

**原则三：懒加载与上下文管理**
Skills不会全部常驻在Agent的上下文窗口中——那样会消耗大量Token。Agent只在需要时加载相关Skill，用完可以卸载。

### 1.3 Skills与工具（Tools）的关系

一个常见的误解是"Skill就是工具"。实际上：

| 维度 | 工具（Tool） | 技能（Skill） |
|------|-------------|-------------|
| **本质** | 一个可执行的功能（读文件、搜网页） | 一套知识+使用工具的规范 |
| **类比** | 扳手、螺丝刀 | "如何修好一辆自行车的完整指南" |
| **创建者** | 需要编程（Python函数） | 只需要写Markdown |
| **粒度** | 原子操作 | 复合能力 |
| **示例** | `write_file`, `web_search` | `github-flow`（教会Agent GitHub协作全流程） |

**Skill = 用自然语言写的"操作手册"，指导Agent如何在特定场景下组合使用各种工具。**

## 二、如何创建第一个Skill

### 2.1 Skill的目录结构

每个Skill是一个独立的文件夹，放在 `~/.hermes/skills/` 下。标准结构：

```
~/.hermes/skills/
└── my-first-skill/
    ├── SKILL.md          # 核心：Skill的定义文件（必需）
    ├── reference.md      # 参考文档（可选）
    ├── examples.md       # 使用示例（可选）
    └── assets/           # 模板、图片等资源（可选）
        └── report-template.md
```

### 2.2 SKILL.md 的标准写法

`SKILL.md` 是Skill的灵魂。一个完整的Skill文件包含以下区块：

```markdown
# Skill: 周报生成器

## 描述
根据项目进展自动生成结构化的周报，支持多种格式导出。

## 触发条件
- 用户说"写周报"、"生成周报"、"本周总结"
- 每周五自动触发（如果配置了cron）

## 适用场景
- 独立开发者向客户/团队汇报进度
- OPC创业者记录每周关键进展
- 多项目并行时的进展汇总

## 你的角色
你是一位专业的项目汇报撰写专家。你的周报特点是：
- 结构清晰：本周完成 → 下周计划 → 风险与阻碍 → 需要的支持
- 数据驱动：每项进展用具体数据支撑
- 简洁有力：总篇幅控制在500字以内，重点突出

## 工作流程
1. 询问用户本周重点关注的项目（如果未指定）
2. 收集信息：检查Git提交记录、文件修改时间、终端历史
3. 按模板填充：将信息整理到标准周报模板中
4. 请用户审核：生成预览，询问是否需要修改
5. 导出：按用户选择的格式导出（Markdown/飞书文档/邮件）

## 周报模板
### 本周完成
- [项目名]：{具体成果，用数据说明}
- ...

### 下周计划
- [优先级1]：{计划做什么，预期成果}
- ...

### 风险与阻碍
- {当前遇到的困难或潜在风险}

### 需要的支持
- {需要谁/什么资源的帮助}

## 限制与边界
- 不要编造数据：如果某个信息获取不到，标注"[待补充]"
- 不要评价好坏：只呈现事实，让读者自己判断
- 不要超出用户指定的项目范围
```

### 2.3 一个实战：创建"每日站会纪要"Skill

让我们动手创建一个真实的Skill。在终端执行：

```bash
mkdir -p ~/.hermes/skills/daily-standup
```

然后创建 `SKILL.md`：

```markdown
# Skill: 每日站会纪要

## 描述
快速生成个人每日站会发言稿，聚焦"昨天做了什么、今天要做什么、有什么阻碍"。

## 触发条件
用户说"站会"、"daily standup"、"今日总结"、"晨会"

## 你的角色
你是我的个人助理，帮我准备每日站会发言。你的风格是：简洁、具体、有重点。

## 工作流程
1. 检查昨天到今天的所有Git commit（git log --since="24 hours ago" --author="$(git config user.name)"）
2. 检查最近修改的文件（find . -mtime -1 -type f）
3. 汇总成三段式发言稿：
   - 昨日完成：基于commit信息
   - 今日计划：询问用户
   - 阻碍项：询问用户
4. 输出格式：
   📋 **昨日完成**
   - {具体任务1}
   - {具体任务2}
   📌 **今日计划**  
   - （请补充）
   🚧 **需要协助**
   - （没有则写：无阻碍，顺利推进中）

## 限制
- 如果Git信息为空，诚实说"昨天没有代码提交记录"，不要编造
- 如果用户是OPC一人公司，将"站会"改为"自我对齐"，语气从"汇报"改为"自检"
```

创建完成后，在对话中说"站会"，Agent就会自动加载这个Skill并按你定义的流程执行。

### 2.4 调试你的Skill：快速迭代方法

Skill开发的"调试七步法"：

1. **写最小可用版本**：先只写核心流程，不要追求完美
2. **加载测试**：`skill_load("daily-standup")` 然后问Agent"站会"
3. **观察行为**：Agent是否按你定义的流程走了？有没有跳过步骤？
4. **修正偏差**：在SKILL.md中加更明确的指令，如"**必须**先询问用户项目名再继续"
5. **边界测试**：测试异常情况——没有Git记录怎么办？用户说"取消"怎么办？
6. **缩减上下文**：如果Skill太长（>2000字），拆分成主文件+reference.md
7. **版本记录**：在SKILL.md底部加 `## 版本历史`，记录每次改了什么

## 三、内置核心Skills详解

### 3.1 GitHub Skill：代码协作大脑

**GitHub Skill** 是最常用的内置Skill之一，它让Agent具备了完整的GitHub操作能力：

**核心能力：**
- 创建/管理 Issue 和 Pull Request
- 代码审查：自动检查代码风格、潜在Bug
- Release管理：自动生成Changelog、打Tag
- Actions监控：查看CI/CD流水线状态
- 项目管理：操作Projects看板

**OPC实战场景**：你口述一个新功能需求，Agent自动创建Issue→写代码→提交PR→等你review→合并→关闭Issue。你实际参与的时间可能只有最后一步review的10分钟。

### 3.2 终端Skill：系统操控权

**终端Skill** 是Agent与操作系统交互的桥梁：

**安全设计：**
- 工作目录沙箱：默认只能在指定项目目录内操作
- 危险命令拦截：`rm -rf /`、`sudo` 等命令需要额外确认
- 输出截断：长输出自动截断，避免Token浪费

**常用场景：**
- 项目初始化：`npm create next-app`、`pip install` 等
- 环境管理：切换Node版本、管理Python虚拟环境
- 文件批量操作：重命名、格式转换、压缩
- 进程管理：启动/停止开发服务器、查看日志

### 3.3 文件Skill：知识库管理

**文件Skill** 让Agent成为你的"第二大脑"管理员：

**操作范围：**
- 读写各种格式：Markdown、JSON、YAML、CSV、代码文件
- 搜索与索引：在大量文件中快速定位内容
- 组织与归档：自动整理项目文档结构

**OPC实战**：你用Notion/Obsidian管理知识库，Agent可以自动同步、格式化、去重你的笔记。比如"把我本周所有会议记录整理成一份知识库索引"。

### 3.4 浏览器Skill：网页世界的代理人

**浏览器Skill** 让Agent可以像人一样操作网页：

**核心操作：**
- 网页内容提取：抓取文章、表格、价格信息
- 表单填写：自动填写重复性表单
- 数据采集：定时抓取竞品信息、行业动态
- Web应用操作：在无法用API的网站上进行自动化操作

**典型场景**：每天早8点自动打开行业新闻网站→抓取头版头条→用AI总结出3个与你业务相关的要点→发到你的飞书。全程无需你参与。

### 3.5 其他值得关注的内置Skills

| Skill | 功能 | OPC价值 |
|-------|------|---------|
| **Web Search** | 实时搜索互联网信息 | 竞品分析、行业研究 |
| **Image Generation** | 调用DALL·E/Midjourney生成图片 | 内容创作、社交媒体配图 |
| **PDF** | 读写PDF文档 | 合同审阅、报告生成 |
| **Notion** | 与Notion工作区交互 | 知识库自动维护 |
| **Email** | 收发邮件 | 客户沟通自动化 |

## 四、社区Skills生态探索

### 4.1 去哪找社区Skills

Hermes Agent拥有活跃的开源社区，Skills是社区贡献最活跃的部分：

- **官方Skills仓库**：`github.com/NousResearch/hermes-skills`（精选Skills集合）
- **社区论坛**：`community.nousresearch.com` 的 Skills 板块
- **Discord**：`#skills-showcase` 频道，用户分享自己的Skills
- **Awesome List**：`github.com/xxx/awesome-hermes-skills`（社区维护的精选列表）

### 4.2 社区热门Skills推荐

以下是在OPC创业者中口碑最好的社区Skills：

**📊 数据分析类：**
- `csv-analyst`：上传CSV，自动生成分析报告和可视化建议
- `sql-query-builder`：用自然语言生成SQL查询
- `google-analytics-reporter`：自动生成GA流量报告

**📝 内容创作类：**
- `twitter-thread-writer`：将一个观点展开为Twitter Thread
- `seo-blog-writer`：根据关键词生成SEO优化的博客文章
- `newsletter-curator`：从多个信息源聚合内容生成Newsletter

**💼 商业运营类：**
- `invoice-generator`：自动生成发票/账单
- `customer-support-triage`：客户咨询分类+自动回复
- `competitor-monitor`：竞品动态监控

### 4.3 评估Skill质量的标准

不是所有社区Skill都值得安装。用这四个标准评估：

1. **维护活跃度**：最近一个月有更新吗？Issue有人回复吗？
2. **文档完整度**：SKILL.md写得清楚吗？有使用示例吗？
3. **安全性**：有没有不必要的工具权限？会不会访问敏感路径？
4. **与你需求的匹配度**：功能是否恰好解决你的问题？还是"大而全但都用不上"？

### 4.4 贡献你的Skill回馈社区

当你的Skill成熟后，回馈社区：

```bash
# Fork官方Skills仓库
git clone https://github.com/NousResearch/hermes-skills.git
cd hermes-skills

# 创建你的Skill目录
mkdir -p skills/my-skill-name
cp ~/.hermes/skills/my-skill-name/SKILL.md skills/my-skill-name/

# 提交PR
git add .
git commit -m "Add skill: my-skill-name"
git push
```

好的Skill文档会包含：清晰的描述、完整的使用示例、已知局限、版本历史。**你贡献的Skill可能帮助成百上千的OPC创业者，这也是建立个人品牌的方式。**

## 五、Skills组合策略：从单技能到技能矩阵

### 5.1 技能成熟度模型

Skills的使用不是"越多越好"，而是"越准越好"。参考这个成熟度模型：

```
Level 1：单技能（Single Skill）
  └── 一次只用一个Skill处理一个任务
      例：用 github-issue-creator 创建Issue

Level 2：技能链（Skill Chain）
  └── 多个Skill按顺序串联，一个的输出是下一个的输入
      例：research-skill 收集资料 → blog-writer 写文章 → image-gen 配图 → social-publisher 发布

Level 3：技能矩阵（Skill Matrix）
  └── 根据任务类型和上下文动态选择合适的Skill组合
      例：收到客户邮件 → 判断类型（投诉/咨询/合作） → 选择不同的Skills链处理
```

大多数OPC创业者应该先精通Level 2（技能链），再逐步构建Level 3（技能矩阵）。

### 5.2 设计一条内容生产技能链

以"每日AI资讯简报"为例，展示技能链设计：

```
[07:00] web-scraper Skill
  └── 抓取5个AI行业的RSS源+3个Twitter账号
  └── 输出：原始素材集合（Markdown格式）

[07:05] content-filter Skill
  └── 按关键词过滤，去重，按重要性排序
  └── 输出：筛选后的10条资讯

[07:10] newsletter-writer Skill
  └── 将10条资讯写成通顺的简报，每条约80字
  └── 输出：Markdown格式的简报草稿

[07:15] image-gen Skill
  └── 根据简报主题生成封面图
  └── 输出：封面图文件路径

[07:20] publisher Skill
  └── 将简报+封面图发布到飞书群/微信公众号/Substack
  └── 输出：各平台发布确认
```

**你实际参与的时间：0分钟。** 你只需要在起床后检查一下质量即可。

### 5.3 构建行业专属技能矩阵

每个OPC创业者的技能矩阵都不同。以下是三个典型画像：

**独立开发者画像：**
```
核心技能矩阵：
  github-flow → cursor-integration → deploy-automation → monitor-alert
```

**内容创作者画像：**
```
核心技能矩阵：
  research → draft → edit → image-gen → seo-optimize → cross-post
```

**AI服务商画像：**
```
核心技能矩阵：
  client-onboarding → requirement-analysis → solution-design → delivery-automation → support-triage
```

**你的技能矩阵应该反映你的核心业务流程。**

### 5.4 技能复用与模块化设计

好的Skills应该像乐高积木——每个都独立可用，但可以组合出各种形态。

**模块化设计原则：**
- Skill A 不依赖 Skill B 的存在——每个Skill都能独立运行
- Skill的输出使用标准格式（Markdown、JSON），方便下一个Skill消费
- 使用"数据契约"模式：Skill A 承诺输出特定格式，Skill B 承诺接受特定格式

**反面案例**：把"写文章+配图+发布+SEO"写在一个Skill里。一旦你想换掉配图方式，整个Skill都要改。

**正面案例**：四个独立Skill，通过标准化的输入输出格式串联。

## 六、Skill调试与迭代优化

### 6.1 Skill开发的"观察-假设-验证"循环

Skill开发是经验科学。核心方法论：

```
观察：Agent执行Skill时的行为
  ↓
假设：为什么行为不符合预期？（指令不够明确？缺少边界条件？）
  ↓
修改：调整SKILL.md中的相关指令
  ↓
验证：重新测试，确认行为改善
  ↓
回到观察（循环）
```

### 6.2 常见的Skill问题与修复

| 问题 | 症状 | 修复方法 |
|------|------|---------|
| **跳跃步骤** | Agent跳过你定义的某一步 | 在关键步骤前加"**必须**先..."、"**强制步骤**：" |
| **过度发挥** | Agent添加了你没要求的内容 | 在"限制"部分加"**严格禁止**..." |
| **理解偏差** | Agent对你的意图理解有误 | 把抽象描述改为具体示例，加examples.md |
| **Token浪费** | 输出冗长、多次重复同样的话 | 加"用一句话回答"、"输出不超过200字" |
| **工具滥用** | Agent频繁调用不必要的工具 | 明确声明"只在X条件下使用Y工具" |
| **上下文迷失** | 对话长了之后行为越来越差 | 在Skill中加"每轮对话开始时先回顾任务目标" |

### 6.3 使用示例驱动开发

在Skill中包含高质量示例是最有效的优化手段。对比：

**❌ 弱指令：**
> "帮我写一篇关于AI的文章"

**✅ 强指令（带示例）：**
> "按以下风格写一篇关于AI的文章：
> **示例开头**：'2023年3月14日，GPT-4发布的那天，我意识到一件事：从今天起，不会用AI的知识工作者，就像1995年不会用搜索引擎的人。'
> **风格要求**：个人视角切入，用具体时间/事件开头，像朋友聊天而非学术报告"

给Agent一个"靶子"远比给一堆"规则"有效。

### 6.4 性能监控与优化

Skills也会影响Agent的性能。关注这些指标：

- **Skill加载时间**：超过1秒说明文件太大，考虑拆分为SKILL.md（核心）+ reference.md（参考资料）
- **Token消耗**：Skill文档本身会消耗上下文窗口。检查SKILL.md的字数，控制在1500字以内（核心流程），详细参考放在单独文件
- **执行成功率**：同一个任务执行10次，成功率低于80%说明Skill需要改进
- **用户干预频率**：你在Agent执行Skill时平均需要干预几次？目标是趋近于0

## 附：实战案例——搭建一条"客户成功"技能链

理论和工具都有了，让我们通过一个完整的OPC实战案例来串联所学内容。

**场景设定**：你运营着一个面向独立开发者的付费社群（500人），每月收入约3万元。你的日常有三类重复工作：（1）新人入群欢迎和引导（2）每周整理群内的优质讨论（3）会员到期提醒和续费跟进。你希望用Skills系统把这三件事自动化。

**Skill 1：新人引导（member-onboarding）**

```markdown
# Skill: 社群新人引导

## 触发条件
- 飞书群有新成员加入
- 用户发送"新人引导"、"开始使用"

## 工作流程
1. 发送欢迎消息（模板）："欢迎加入XXX社群！👋 以下是快速上手指南..."
2. 引导新人完成3个动作：修改群名片→阅读置顶文档→自我介绍
3. 24小时后检查：如果新人还没完成上述动作，私聊提醒
4. 标记：将新人信息记录到 ~/community/members.csv
```

**Skill 2：周报生成（weekly-digest）**

```markdown
# Skill: 社群每周精华整理

## 触发条件
- 每周五下午5点自动触发

## 工作流程
1. 抓取本周群内所有消息（通过飞书API）
2. 按回复数+点赞数筛选"最热讨论Top 5"
3. 对每个热门讨论用AI生成100字摘要
4. 收集本周分享的优质资源链接
5. 按模板生成周报：热点讨论｜精华资源｜下周预告
6. 发布到群公告+归档到 ~/community/digests/
```

**Skill 3：续费管理（renewal-manager）**

```markdown
# Skill: 会员续费管理

## 触发条件
- 每天上午9点检查到期名单

## 工作流程
1. 查询 members.csv，筛选"7天内到期"的会员
2. 对每个即将到期的会员，生成个性化续费提醒
   - 包含：会员加入时长、参与讨论次数、个人成长总结
3. 到期前7天/3天/1天各提醒一次
4. 到期后3天未续费：发送"我们会想你的"告别消息+回归优惠码
5. 更新续费状态到 members.csv
```

**把三条链串起来：OPC社群运营全自动化**

这三个Skill不是孤立运行的。它们共享 `members.csv` 作为数据中心，形成了一个完整的社群运营自动化体系：

```
新成员加入 → member-onboarding 自动欢迎+引导
   ↓（数据写入 members.csv）
每周五 → weekly-digest 自动生成精华周报
   ↓
每天9点 → renewal-manager 自动检测+提醒续费
   ↓
整个系统 → 你每周只需要花30分钟review + 做战略性决策
```

**实施效果评估**：

| 工作项 | 人工耗时（前） | 人工耗时（后） | 节省 |
|--------|-------------|-------------|------|
| 新人引导 | 15分钟/人 × 20人/月 = 5小时 | 30分钟/月（抽查） | 4.5小时 |
| 周报整理 | 2小时/周 × 4 = 8小时/月 | 30分钟/月 | 7.5小时 |
| 续费管理 | 1小时/周 × 4 = 4小时/月 | 15分钟/月 | 3.75小时 |
| **合计** | **17小时/月** | **1.25小时/月** | **15.75小时/月** |

**每月省出近16个小时。这些时间可以用来做产品、做内容、探索新方向——真正的高杠杆工作。** 而这三个Skill的开发总投入，大约是2-3个下午。

**这个案例的核心启示**：Skills的价值不在于"一个Skill多强大"，而在于"多个Skill能否形成闭环"。每个Skill解决一个环节，串起来就能自动化整条业务线。

---

## 小结

Skills系统是Hermes Agent最强大的扩展机制，也是OPC创业者"复制自己能力"的关键。一个好的Skill就是"把你的隐性知识显性化"——把你头脑中"知道怎么做但说不清楚"的东西，变成AI可以可靠执行的操作指南。

起步建议：**先用内置Skills熟悉系统 → 挑一个你每天做的重复任务创建第一个Skill → 用一周时间打磨到"不需人工干预" → 然后构建2-3个Skill的技能链。**不要贪多，一个真正好用的Skill胜过十个半成品。
